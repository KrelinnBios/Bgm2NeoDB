# 本地部署、标题匹配与迁移的历史选择

此文件是项目内部的专项维护规则。根目录 [AGENTS.md](../../AGENTS.md) 仍然适用。

## 已确立的决定

### 为什么使用本地运行而不是网页服务？

用户的 Bangumi 和 NeoDB 凭证不应上传到第三方服务器。本地运行确保凭证只在用户自己的机器上使用。

### 为什么不使用标题模糊搜索？

模糊搜索容易产生误匹配。项目优先使用来源链接匹配（Bangumi ID），其次是精确标题匹配，多个候选时由用户手动确认。

### 为什么搁置状态不迁移评分？

Bangumi 的"搁置"通常表示暂停，不代表最终评价。NeoDB 没有对应的"搁置"状态，迁移为"在看"后保留评分可能误导。

### 为什么不删除 NeoDB 现有收藏？

迁移工具只负责从 Bangumi 向 NeoDB 同步收藏，不应删除 NeoDB 独有的收藏或数据。

### 为什么使用独立的并发限制？

解析和写入是两个独立阶段。解析并发过高会触发 API 限流，写入并发过高会导致回读核对时读到旧数据。当前的 6/10 限制是优化后的平衡值。

### 为什么最后一轮解析共用 60 秒超时？

NeoDB 未收录的条目需要实时抓取外部元数据，抓取可能需要数秒到数十秒。第一轮遇到抓取中的条目会先跳过，让快速条目先写入；最后一轮重试时剩余条目共用 60 秒的等待时间，处理过程中会显示剩余时间和总用时。

### 为什么不自动重试所有失败条目？

网络临时错误（超时、503）可以自动重试，但解析失败、映射冲突、隐私校验失败等问题需要用户介入。自动反复重试会掩盖真实问题。
