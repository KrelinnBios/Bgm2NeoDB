## 项目简介

Bgm2NeoDB 是一个本地网页工具，用于将 Bangumi 收藏迁移到 NeoDB 或兼容实例。程序在本机 `127.0.0.1:8765` 运行，无需部署网站、配置环境变量或填写账号密码。

通过 Bangumi 个人凭证和 NeoDB OAuth 授权连接两个平台，扫描 Bangumi 收藏、查看迁移差异、批量迁移条目并检查结果。

## 功能概览

- 账号连接：通过 Bangumi 个人凭证和 NeoDB OAuth 授权连接，凭证保存在系统凭证库或内存中。
- 收藏扫描：读取 Bangumi 完整收藏数据到本地数据库，支持重新扫描。
- 迁移预览：自动解析 Bangumi 条目到 NeoDB，生成迁移计划与差异对比。
- 批量迁移：高并发处理收藏状态、评分、短评、标签与可见性，按规则合并现有数据。
- 失败处理：在迁移记录中查看失败原因并重试失败条目。
- 暂停恢复：迁移任务可暂停与继续，已完成条目不重复处理。

## 安装与启动

需要 Python 3.11 或更新版本，推荐 3.12。

### Windows：双击启动

首次使用先在项目目录执行一次安装（在 PowerShell 里运行）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

之后**双击项目根目录的 `start.bat`** 即可启动。脚本会自动用虚拟环境运行，浏览器稍后自动打开网页，无需敲命令。

### 命令行启动

Windows PowerShell：

```powershell
.\.venv\Scripts\python.exe main.py
```

macOS / Linux：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

如果你已经启用了虚拟环境，也可以直接运行：

```bash
python main.py
```

程序会自动打开浏览器。没有自动打开时，手动访问 [本地操作页面](http://127.0.0.1:8765)。关闭浏览器不会停止任务；在运行程序的终端按 `Ctrl+C` 可以停止程序。

无界面启动：`python main.py --no-browser`。端口被占用时会提示，避免误打开其他程序。

## 使用方式

### 基本流程

1. **连接 Bangumi**：打开 [Bangumi 官方授权凭证页面](https://next.bgm.tv/demo/access-token)，创建 Access Token 并粘贴。
2. **连接 NeoDB**：填写实例地址（默认 `https://neodb.social`），完成 OAuth 授权。
3. **扫描收藏**：读取 Bangumi 完整收藏数据并保存到本地数据库。
4. **自动迁移**：扫描完成后直接解析、写入并核对。快速匹配的先写入，解析未通过的最后重试。
5. **查看结果**：在迁移记录中查看状态、差异和失败原因。

### 自动执行与继续

- 自动补充 Bangumi 官方别名，汇总 NeoDB 搜索分页；来源链接匹配优先于名称匹配。
- 多个版本、自动匹配时的重复目标和不完整搜索结果会保存候选与具体原因，不会被下一轮统一改写为超时；人工确认后按所选目标处理当前条目。
- 在条目详情中查看保存的候选，必要时点击“重新查找候选”。确认选择后会保存人工映射并只迁移当前条目，重新扫描仍会保留。
- 没有 NeoDB 链接时，可直接在详情中粘贴作品外链，点击“按链接导入”。程序只把链接交给已连接的 NeoDB 实例解析，不直接创建 NeoDB 条目；未收录的作品由 NeoDB 实例自行尝试抓取或创建，成功后保存映射并只迁移当前收藏。支持哪些来源取决于该实例。
- 手工按链接导入会先立即提交给 NeoDB；未收录的普通作品在后台抓取期间会自动轮询，页面最多等待 60 秒并显示倒计时，不需要重复点击。不支持的链接或抓取失败会在弹窗内显示原因并保留输入，可换链接或稍后重试。候选选择和按链接导入均遵守”导入收藏日期”开关。
- 如果 NeoDB 没有对应条目，请使用详情中的“在 NeoDB 创建条目”按钮前往创建页面；书籍、音乐和游戏分别进入 `Edition`、`Album` 和 `Game`，动画及三次元作品会根据 Bangumi 的平台信息判断进入 `Movie`、`TVShow` 或 `Performance`。平台信息不足以判断时不显示入口。创建完成后，再把 NeoDB 条目链接粘贴回来绑定。本工具不会代替 NeoDB 提交创建表单。
- 自动继续仅重试临时问题和未完成的写入；需要确认的条目不会反复请求。详见[匹配与恢复设计](docs/RESOLUTION.md)。

- 点击”开始自动迁移”，扫描完成后自动开始迁移，不再需要手动预览和确认写入。
- 所有匹配成功且通过数据检查的条目都会实际写入 NeoDB，内容一致也不跳过；只有写入返回成功且回读核对一致，才标记为”迁移成功”。
- 第一轮快速解析，暂时需要等待抓取或解析失败的条目留到最后重试一次，每条独立享有最多 60 秒的解析等待时间，避免拖住能立即迁移的作品。
- 每条 60 秒超时独立计算，处理过程中会显示当前条目剩余时间和总用时。超时后未解析条目会保留明确原因，已经开始写入的条目继续完成回读核对。
- 写入或核对失败会暂停整批任务，不再自动反复写入；已发出的请求完成核对并保存进度。处理问题后点击“继续自动迁移”。
- 旧版”无需改动”记录显示为”待补写（旧记录）”，会自动补写，不计入已完成。
- 自动继续时不重复写入已确认成功的条目。重新扫描时，已成功迁移的条目会被跳过，不会重复处理。”重启”按钮会重新读取 Bangumi 收藏。
- NeoDB 授权需在同一浏览器完成，不要复制回调链接。程序重启后需重新发起未完成的授权。

## 附录

### 迁移规则详情

| Bangumi | NeoDB |
|---|---|
| 想看 | 想看（wishlist） |
| 看过 | 看过（complete） |
| 在看 | 在看（progress） |
| 搁置 | 在看（progress），不导入 Bangumi 评分 |
| 抛弃 | 抛弃（dropped） |

- 有效评分 `1–10` 原样迁移；`0` 表示未评分。
- **搁置不迁评分**：新收藏不设置评分；NeoDB 已有评分会保留，不会因为迁移被清空。
- 非空短评按原文迁移为短评，替换该作品当前短评；空短评保留 NeoDB 原文。不添加来源文字，也不创建长评。
- 标签只去掉首尾空白、空标签和重复项；与 NeoDB 现有标签合并，保留目标端独有标签。不新增"导入""搁置"等标签。
- Bangumi 私密收藏写为私密；如果 NeoDB 原来更私密，不降低它的可见性。无法确认隐私数据时阻止该项。
- 不自动向联邦时间线发布迁移动态。
- 不使用标题模糊搜索，不删除 NeoDB 里的其他收藏。
- 多个 Bangumi 收藏解析到同一 NeoDB 作品时，标记冲突并停止这些条目的自动迁移；在详情中确认目标后，会按当前条目的收藏内容写入。

### 暂停、恢复与重试

- **暂停**：点击上方主按钮“暂停”。停止发起后续操作，已写入但尚未核对的条目保留为待核对状态。
- **继续自动迁移**：先处理未完成的快速条目，最后重试未通过的条目；已确认成功的不重复写入。
- **自动暂停**：写入请求失败、回读核对失败或账号失效时停止，保留当前进度和具体错误。
- **解析仍未通过**：最后一轮重试后保留失败状态，显示剩余数量，不循环重试或误报全部成功。
- **重启**：重新扫描 Bangumi 并开始自动迁移。

### 常见问题

**一直显示正在解析？** 自动迁移的部分条目需要 NeoDB 异步抓取元数据。按链接导入会先提交任务并自动轮询；自动迁移第一轮遇到抓取中或限流会先留到最后，最后一轮每条独立享有最多 60 秒的解析等待时间，期间仍可暂停。超过时限会保留为解析失败，可稍后继续重试。

**为什么比 Steam 迁移慢？** Steam 游戏基本都在 NeoDB 数据库里，Bangumi 条目覆盖率因类型而异，不存在的需实时抓取。

**提示作品合并或检查后变化？** 自动迁移会暂停。查看条目详情后继续自动迁移，程序会重新读取现有内容；多个 Bangumi 条目对应同一 NeoDB 作品的冲突需要手工处理。

**如何加速？** 程序自动优先处理快速匹配的条目，不等待整批慢条目解析结束才写入。

**安装时找不到依赖？** 检查网络及 Python 版本，或运行 `python -m pip install --index-url https://pypi.org/simple -r requirements.txt`。

自建实例目前支持标准 HTTPS 公网域名（443 端口），不支持子路径、内网地址或自签名证书。

## 性能与限制

程序采用并发解析（最多 6）和写入（最多 10），快速匹配的条目立即进入写入核对，慢条目最后重试。实际速度取决于：

- **NeoDB 条目覆盖率**：未收录的条目需要请求目标实例实时抓取；本工具不直接创建条目。最后一轮每条独立享有最多 60 秒的解析等待时间，超时后保留失败状态。
- **服务端限流**：抓取请求至少间隔 3 秒；收到抓取中或限流响应后，同一来源至少等待 15 秒再查，并尊重服务器的 `Retry-After`。限流仍可能发生，不保证所有请求立即成功。

典型场景：热门作品快（多数已存在），冷门/老旧作品慢（需实时抓取）。普通请求间隔 0.05 秒，不支持的条目（422/404）立即结束该次抓取。解析和写入使用独立的并发名额；单条读取按编号查询，已迁移目标判重使用数据库索引，避免每处理一项就读取完整收藏数据。

## 数据存储

项目的 `data/` 目录保存本地记录；两个账号和 NeoDB 实例的不同组合会隔离存放，避免切换账号后用错迁移记录。

```text
data/
├── migration.db                 收藏原文、条目映射、计划与迁移状态
├── migration.log                不含凭证的阶段日志（记录操作成功、失败和状态变化）
└── profiles/<账号组合编号>/      当前账号组合的迁移记录
```

迁移记录含你自己的收藏、短评、标签等个人内容，已在 `.gitignore` 中排除，不要在 GitHub Issue 中直接公开。

程序不会执行删除收藏或自动回滚。迁移记录中的差异和状态用于检查结果，不提供一键回滚功能。

## 隐私与数据

- Bgm2NeoDB 不会要求或保存你的 Bangumi / NeoDB 密码。
- Bangumi 采用官方个人授权凭证方式；NeoDB 使用动态注册的 OAuth 应用与随机、限时、一次性的回调验证。
- 连接成功的凭证优先保存在操作系统凭证库；凭证库不可用时只留在内存，页面会提示重启后需要重新连接。
- 凭证不写入数据库或日志；程序不会把认证头跟随跳转发送到其他实例。
- 本地页面限制 Host，并校验会话、请求来源和防跨站请求凭证。
- "断开"移除本程序本地保存的连接；如需撤销平台授权，还应到对应平台的授权管理页操作。
- 收藏数据和迁移记录保存在本地 `data/` 目录，不会上传到远程服务器。

## 内容边界

- 本项目为个人迁移工具，与 Bangumi、NeoDB 及各实例运营方无隶属关系。
- 迁移工具仅处理收藏状态、评分、短评、标签与可见性，不迁移日志、长评、目录、人物收藏、角色收藏、好友关系、章节吐槽和其他社交数据。
- 进度目前不写入 NeoDB；收藏日期可选导入，默认勾选但可关闭。
- 不自动向联邦时间线发布迁移动态，不使用标题模糊搜索，不删除 NeoDB 里的其他收藏。
- 请遵守所连接平台的服务规则、内容规范和所在地法律法规。
- 平台数据分别适用对应平台及权利人的条款、隐私政策及权利声明。
